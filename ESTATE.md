# KHE estate

Canonical navigation index for the KHE estate. It lives in the public
[`khe-architecture`](https://github.com/khelias/khe-architecture) repo,
beside the estate's decisions in [`decisions/`](decisions/).

Loaded automatically as workspace-level context for Claude Code working
in `<KHE_ROOT>/`, the checkout of the [`khe-workspace`](https://github.com/khelias/khe-workspace)
workspace repo: its `CLAUDE.md` `@`-imports this file from
`repos/khe-architecture/ESTATE.md`. Codex and other agents.md-only tools do not see
this file (the spec does not support `@`-imports); they read
`<KHE_ROOT>/AGENTS.md` (personal prefs), which points here by path. When in doubt
about which repo owns what, start here.

## Where things deploy

- **Homelab** (Proxmox VM at home, behind Cloudflare Tunnel) hosts the public `khe.ee`, `games.khe.ee` and its sub-paths (`/study`, `/adventure`), `pages.khe.ee` and the khe-trips share sites at `khe.ee/r/<slug>/` and demo at `khe.ee/trips/` (landing container); `trips.khe.ee`, `stories.khe.ee`, `dash.khe.ee`, `status.khe.ee` and `draft.khe.ee` behind Cloudflare Access, all but draft with a home route that skips it on the home network and over Tailscale ([ADR-022](decisions/022-home-route-for-access-only-apps.md)); `photos.khe.ee` and `vault.khe.ee` on the tunnel behind their own app login; and the LAN-only services in `khe-homelab/services/` (Home Assistant, AdGuard, NPM admin, Grafana). The khe-stories builds that khe-bunny-tales deploys live there: the family build at `stories.khe.ee`, the public one at `khe.ee/stories/` from the landing container, and their audio store on the homelab disk, in the restic offsite backup ([ADR-031](decisions/031-stories-public-app-private-stories-audio-outside-git.md)). The tunnel and Access tables are in `khe-homelab/infrastructure/cloudflare.md`. A second VM there, `agent-vm`, runs the operator's Claude Code workspace agent, reached through Remote Control ([runbook](https://github.com/khelias/khe-homelab/blob/main/infrastructure/agent-vm.md)), for the sessions the operator steers; agent jobs that run without the operator run on GitHub-hosted Actions, never in the homelab ([ADR-027](decisions/027-attended-and-unattended-agent-tiers.md)).
- **GHCR** (`ghcr.io/khelias/*`, public packages) holds the images the estate builds in CI; `khe-homelab` pins them by digest and each app's CI moves its pins through an auto-merging PR ([ADR-008](decisions/008-container-images.md)). `khe-ai-adventure` is the first app on it.
- **npmjs** holds `@khelias/ui` from `khe-ui`, published by a tag-triggered workflow on a GitHub-hosted runner through trusted publishing with provenance, no stored token. Each app pins it and merges its own bump; no consumer automerges it ([ADR-014](decisions/014-shared-ui-packages.md)).
- **GitHub** renders `khelias/khelias` on the profile page.
- **Cloudflare Workers** hold a fallback copy of the static `khe.ee` and `games.khe.ee` sites (not `trips.khe.ee` or `stories.khe.ee`, and `khe.ee/stories/` without its audio, [ADR-031](decisions/031-stories-public-app-private-stories-audio-outside-git.md)), served on the two routes only when the homelab answers 5xx or not at all. `khe-homelab` owns the Worker and syncs the copy hourly from what the homelab serves ([ADR-016](decisions/016-static-fallback-at-the-edge.md)). The Worker `makett-preview` serves khe-makett's sales site preview on its custom domain `makett.khe.ee`, behind Cloudflare Access, deployed by khe-makett's CI from a GitHub-hosted runner.

## Adding a repo

Besides this index and `repos/repos.yaml`:

- **Naming:** `khe-workspace` was `khe` until 2026-10-07, and GitHub redirects the old name only while no repo takes it. Never give `khe` or `khe-ai-rules` to a new repo.
- **Public:** the default-branch ruleset from [ADR-023](decisions/023-agent-pushes-where-its-session-allows.md) (deletion + non-fast-forward, no bypass actors; classic branch protection where that is what the repo has), plus the CI status check if it deploys, which does not bind admins so an emergency push stays possible. A repo on the pull request route also requires the personal-data scan, allows auto-merge, merges with a merge commit and is marked `pr: true` in `repos/repos.yaml` (ADR-023 point 3). Its CI scan is khe-workspace's `scripts/pii-scan-range.sh` with the commit gate's rules, checked out at a pinned commit.
- **What GitHub shows:** its `description:`, `homepage:`, `topics:` and `visibility:` in `repos/repos.yaml`, applied with the commands `scripts/docs-check.py --meta` prints; wiki and projects off. A public repo also turns on private vulnerability reporting (`gh api -X PUT repos/khelias/<name>/private-vulnerability-reporting`), where the default `SECURITY.md` in `khelias/.github` sends reports. A repo-specific `SECURITY.md` adds to that default and links it.
- **Public with a homelab runner:** fork PR approval `all_external_contributors`, and a fork run is approved only after reading its `.github/workflows/` diff (ADR-023 point 5). A private repo needs no such setting: only collaborators can fork it.
- **Renovate:** `renovate.json` alone does nothing. The repo also has to be added to the Renovate app's repository selection at <https://github.com/settings/installations>. The Dependency Dashboard issue appearing is the proof that it runs.
- **Ships a container image:** a pin App of its own (like `khe-adventure-pins`: Contents and Pull requests write, installed on `khe-homelab` only), a `homelab-pin` environment limited to `main` holding its secrets, one `PIN_APPS` line in homelab's `validate.yml` and one `source_repo` entry in `scripts/verify-estate-pins.sh` ([ADR-008](decisions/008-container-images.md)). The first publish creates each GHCR package private; make it public once in its package settings. A private repo has no attestations on GitHub Free, so decide the pin check first.
- **Publishes to npm:** the package page's trusted publisher (owner, repo, workflow file, environment) and Publishing access that requires 2FA and disallows tokens. Trusted publishing works only from a GitHub-hosted runner, and the package must exist first, so the first version is published by hand. Every consumer's Renovate config turns automerge off for the package ([ADR-014](decisions/014-shared-ui-packages.md)).
- **Installable web app** ([ADR-041](decisions/041-installed-apps-stay-on-their-paths-with-a-worker-each.md)): a manifest with its own `id`, `scope` and `start_url` on the app's path, `name`, `short_name`, `display: standalone`, `theme_color` and `background_color`; icons of 180 (opaque, for iOS), 192 and 512, and a separate maskable 512 with its content inside the central 80%; head tags for the manifest, `theme-color`, `apple-touch-icon`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-title` and `viewport-fit=cover`; a hand-written worker with its own cache prefix, an atomic precache, so an install that misses a file a deploy has deleted fails and the previous worker stays in use, and cleanup of that prefix only, with no API path and no file the container writes from a secret at start in it; a tested kill-switch and `sw.js` kept at its URL for good; `no-cache` on the manifest and the HTML and `private, no-cache` on `sw.js`, since Cloudflare rewrites a plain `no-cache` on a `.js` file to its four-hour browser cache; `application/manifest+json` from an exact-match nginx location, since a server-level `types` block would replace the whole map; `sw.js` passed through to the origin by the edge fallback when the site has one.
- **Private:** no branch rules (ADR-023 point 4). GitHub Free has no auto-merge there. `gh api -X PATCH -F allow_auto_merge=true` answers 200 and leaves the field `false`, so do not spend time on it. Renovate's `platformAutomerge` falls back to its own merge.
